## 1. 这是什么

两块功能,源自 `K:\new-api\new-api-1.0.0-rc.15`(rc.15 参考实现):

1. **灵境 JDCloud 渠道**:把京东云灵境 Cinema2.0 视频生成作为 new-api 原生渠道接入。客户端走 OpenAI 风格 `/v1/video/generations`,new-api 内部翻译成灵境 `ydSubmitTask`/`queryTasKResult` 协议。
2. **视频地址本地化**:上游视频任务完成后,把视频下载到本地,对外只返回本地直链 `/api/videos/<task_id>.mp4`(无签名、无过期、强制下载),避免泄露上游 OSS 地址;配套后台「视频下载」管理页(列表/重试/删除/设置)。

设计依据见同目录:`灵境Cinema2.0-new-api接入说明.md`、`视频地址本地化-方案设计.md`、`视频生成API-对接文档.md`。

## 3. 目标与 rc.15 的关键差异(决定了移植要适配的点)

目标比 rc.15 新,探查结论(三个 Explore 代理 + 直查):

1. **渠道类型号 59/60 已被占用**:rc.15 用 `ChannelTypeJDCloud = 59`,但目标里 59=`Sub2API`、60=`NewAPI`。→ 本移植改用 **`ChannelTypeJDCloud = 61`**(前后端一致)。
2. **`OpenAIVideo` 系列换了包**:rc.15 在顶级 `dto` 包;目标挪到了 `relaykit/dto`(顶级 `dto` 只剩 `TaskError` 等)。→ `jdcloud/adaptor.go` 的 import 要拆:`taskdto ".../dto"` + `".../relaykit/dto"`,`*dto.TaskError`→`*taskdto.TaskError`,而 `dto.NewOpenAIVideo()`/`dto.OpenAIVideoError` 仍用 `dto.`(解析到 relaykit)。
3. **`model/main.go` 有两个迁移函数**:`migrateDB()`(顺序)和 `migrateDBFast()`(并发)。→ `VideoDownload` 要加进**两处**(rc.15 只有一处)。
4. **前端目录不同**:rc.15 是 `web/default/src/...`;目标是 `web/src/...`(无 `web/default/`),构建用 rsbuild + TanStack 文件路由(同模型,仅位置迁移)。`routeTree.gen.ts` 由插件自动生成,**勿手改**。
5. **结构兼容的点**:`TaskModel2Dto`、`dto.TaskResponse[any]`、`TaskAdaptor` 14 方法、`taskcommon.BuildProxyURL`、`SystemTask{}`/`SystemTaskLock{}`、Task 结构体字段(`PrivateData.ResultURL`/`TaskID`/`UserId`/`ChannelId`)在目标都还在,只是行号位移。门控落点在 `relay/relay_task.go` 的 `videoFetchByIDRespBodyBuilder`(目标没有 `controller/task_video.go`,已并入此处)。
