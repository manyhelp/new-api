# 视频地址本地化（下载代理）· 方案设计

> 目标：把上游平台返回的视频文件**下载到本地存储**，对外只返回**本地（网关）地址**，彻底避免泄露上游平台信息（如 OSS 域名 / 路径 / 桶名等）。并配套一个后台「下载列表」栏目做管理与重试。
>
> 本文档为方案设计，不含最终代码实现。
>
> 📌 **实现订正（2026-07）**：最终对外地址采用**干净直链** `/api/videos/<task_id>.mp4`（**无签名、无过期**、浏览器强制下载），而非下文早期设想的 `?sig=&expires=` 签名 URL；`data.data` 改为只回显**脱敏后的请求参数**（`request_params`）；新增 `VideoLocalizePublicBaseURL` 控制对外域名（查询时实时生成）。下文涉及签名/过期的描述以此订正为准。

---

## 1. 背景与问题

- 现状：视频任务完成后，`result_url` 直接返回上游平台的视频地址，例如：
  `https://<平台OSS域名>/<平台桶>/.../xxx.mp4` —— 暴露了上游平台身份与存储结构。
- 对外响应里的 `data.data`（上游原始返回）同样包含平台地址。
- 需求：用户拿到的地址必须是**本网关的地址**；上游地址仅保存在内部用于下载/重试，绝不外泄。

## 2. 设计目标（对应你的 5 条需求）

| 需求 | 方案落点 |
|---|---|
| ① 下载到本地 + 本地地址映射 | 视频本地化管线（§4）+ 本地文件服务路由（§8） |
| ② 按任务 ID 的 CRUD、平台数据入库 | 新表 `video_downloads`（§5）+ 后台栏目（§7） |
| ③ 异常文件可按任务 ID 重试 | 重试入队（§6.4、§7） |
| ④ 最大并发下载数可配 | 下载工作器并发池（§6.2）+ 系统设置（§9） |
| ⑤ 没下完不返回"已完成"、不返回平台数据 | 查询门控（§6.5）+ 响应脱敏（§6.6） |

## 3. 总体架构

```
上游平台生成完成(远程视频URL)
        │  (任务轮询检测到 SUCCESS + 远程 URL)
        ▼
【本地化入队】创建 video_downloads 记录(pending, 仅内部存 source_url)
        ▼
【下载工作器】(信号量限并发) 下载文件到本地 data/video_files/<task_id>.mp4
        ▼
【完成】写 local_path / public_url，status=success
        ▼
【查询门控】用户查询时：
        - 未下完 → 对外 status=IN_PROGRESS，不返回任何 URL / 平台数据
        - 已下完 → 对外 status=SUCCESS，result_url = 本地地址
        ▼
【本地文件服务】 GET /api/videos/<task_id>.mp4  流式返回本地文件(强制下载,支持Range)
```

关键原则：**上游远程地址只进 `video_downloads.source_url`（内部字段），任何对外响应都不出现它。**

## 4. 触发时机（本地化入队）

- 新增系统开关 `VideoLocalizeEnabled`（默认关）。
- 在任务轮询（`service/task_polling.go`）解析到「上游成功 + 远程视频 URL」时：
  - 若开关关：维持现状（直接把远程 URL 写入 `task.ResultURL`）。
  - 若开关开：
    1. **不**把远程 URL 写入对外字段；
    2. `INSERT` 一条 `video_downloads`（status=`pending`，`source_url`=远程地址）；
    3. `task` 内部可标记为「上游成功但待本地化」，对外状态由查询门控决定（§6.5）。
- 通用性：按「该任务是否存在远程 result URL」判断，适用于所有视频渠道，不绑定单一上游。

## 5. 数据模型

新增表 `video_downloads`（需同时兼容 SQLite / MySQL / PostgreSQL，遵循 GORM 规范）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | uint | 主键 |
| `task_id` | string, index | 关联 `tasks.task_id`（建议唯一索引或"最新一条"） |
| `user_id` | int | 归属用户 |
| `channel_id` | int | 渠道 |
| `source_url` | string(text) | **上游远程地址（内部保密，不对外）** |
| `local_path` | string | 本地存储相对路径，如 `video_files/<task_id>.mp4` |
| `public_url` | string | 对外本地地址（含签名） |
| `status` | string | `pending` / `downloading` / `success` / `failed` |
| `file_size` | bigint | 已下载字节数 / 最终大小 |
| `mime_type` | string | 如 `video/mp4` |
| `error` | string | 失败原因 |
| `retry_count` | int | 已重试次数 |
| `created_at` / `updated_at` | time | 时间戳 |

CRUD（对应需求 ②）：
- 增：入队时创建；
- 查：列表分页（按 task_id / status 过滤）、单条按 task_id 查；
- 改：重试（重置 status=pending, 清 error）、并发数等设置；
- 删：删除记录 **并删除本地文件**（可配是否保留文件）。

## 6. 下载管线

### 6.1 存储布局
- 目录：系统设置 `VideoLocalizeDir`（默认 `data/video_files/`）。
- 命名：`<task_id>.mp4`（避免覆盖；任务 ID 已唯一）。
- 写入采用临时文件 + 完成后 rename，防止半成品被当作成品。

### 6.2 并发控制（需求 ④）
- 后台 goroutine 工作池，从 `status=pending` 按创建时间拉取。
- 用信号量（buffered channel）限制并发，上限 = `VideoLocalizeConcurrency`（默认 3）。
- 并发数变更后，工作器在下一轮调度生效（无需重启，热加载设置）。

### 6.3 下载执行
- `GET source_url`，流式写入临时文件；记录 `file_size`、`mime_type`。
- 单文件超时 `VideoLocalizeTimeout`（默认 120s）。
- 完整性校验：比对 `Content-Length`（若上游提供）；可选 MD5 校验。
- 成功 → rename 到最终路径，生成 `public_url`（§8），`status=success`。
- 失败 → `status=failed`，写 `error`，`retry_count++`。

### 6.4 重试（需求 ③）
- 后台「下载列表」每条 failed 记录可点【重试】：`status=pending`, `error=""`, 重新入队。
- 最大重试次数 `VideoLocalizeMaxRetry`（默认 3），超限后标 `failed` 且不再自动重试（仍可手动强制重试）。
- **上游时效窗口**：远程地址通常有时效（如 90 分钟）。重试须在窗口内；若已过期且下载未成功，标记 `expired`（属于 failed 的子态），后台提示「需重新生成任务」。

### 6.5 查询门控（需求 ⑤，最关键）
GET `/v1/video/generations/{task_id}`（及 `ConvertToOpenAIVideo` 路径）在本地化开启时按 `video_downloads.status` 决定对外状态：

| download 状态 | 对外 `data.status` | `result_url` | `data.data`（上游原始） |
|---|---|---|---|
| `pending` / `downloading` | `IN_PROGRESS` | **不返回** | **不返回** |
| `success` | `SUCCESS` | **本地 public_url** | 不返回（或脱敏） |
| `failed` / `expired` | `FAILURE` | 不返回 | 不返回 |
| 未开启本地化 | 维持现状 | 远程 URL（旧逻辑） | 原样 |

> 即"用户可见的完成"以**本地下载完成**为准；下载未完成前一律不返回成功、不返回任何平台数据。

### 6.6 响应脱敏（隐私）
- 对外响应中**移除** `data.data`（上游原始返回），或至少剔除其中所有 URL 字段，确保平台地址不外泄。
- `result_url`、`metadata.url` 一律替换为本地地址（或留空）。
- 仅在后台「下载列表」内部界面可见 `source_url`（管理员）。

## 7. 后台「下载列表」栏目

新增一级或二级菜单：**视频下载 / 下载列表**。

### 7.1 列表页
- 列：`task_id`、状态、文件大小、创建/完成时间、`error`、操作。
- 过滤：按 `task_id` 精确查、按状态筛选、按时间范围。
- 操作：
  - **重试**（failed/expired → pending，重新入队）
  - **复制本地地址**（success 时）
  - **删除**（删记录 + 本地文件，二次确认）
  - **查看**（详情：管理员可见 source_url、retry_count 等）

### 7.2 设置区（栏目内或系统设置）
- 启用开关 `VideoLocalizeEnabled`
- 最大并发 `VideoLocalizeConcurrency`
- 存储目录 `VideoLocalizeDir`
- 单文件超时 `VideoLocalizeTimeout`
- 最大重试 `VideoLocalizeMaxRetry`
- 保留天数 `VideoLocalizeRetainDays`（可选自动清理过期文件）

## 8. 本地文件服务（对外地址来源）

- 路由：`GET /api/videos/<task_id>.mp4`，流式返回本地文件（`Content-Disposition: attachment` 强制下载，支持 Range/拖动）。
- `public_url` 形如：`https://<网关对外域名>/api/videos/<task_id>.mp4`（**干净直链，无签名、无过期**）。
- 鉴权：直链**无需令牌**，靠 `task_id`（随机不可猜）保护；如需收紧可后续改为令牌校验（当前未启用）。
- 公网 BaseURL：`VideoLocalizePublicBaseURL` 配置对外域名，查询时实时生成、改完立即生效（为空回退系统 `ServerAddress`）。
- 防路径穿越：`local_path` 必须落在 `VideoLocalizeDir` 内，禁止 `..`。

## 9. 配置项汇总（系统设置）

| 配置 | 默认 | 说明 |
|---|---|---|
| `VideoLocalizeEnabled` | false | 总开关 |
| `VideoLocalizeConcurrency` | 3 | 最大并发下载数 |
| `VideoLocalizeDir` | `data/video_files/` | 本地存储目录 |
| `VideoLocalizeTimeout` | 120s | 单文件下载超时 |
| `VideoLocalizeMaxRetry` | 3 | 最大重试次数 |
| `VideoLocalizeRetainDays` | 0（不清理） | 本地文件保留天数 |

## 11. 边界与风险

- **上游时效**：远程地址一般 90 分钟有效；下载须在窗口内完成，失败且过期需重新生成。建议：上游成功后**立即入队**，并把下载优先级置于轮询之前。
- **磁盘占用**：视频文件较大，需保留策略 + 磁盘水位告警；删除任务时联动清理文件。
- **"可见完成"延迟**：本地化会让用户晚一点看到完成（多了下载耗时）。可接受范围一般在数秒到几十秒；大文件/低带宽下更久，需在文档/UI 提示"转存中"。
- **带宽**：并发下载 + 用户回拉本地文件，会占用网关出/入带宽；并发数需结合带宽调。
- **单点存储**：本地磁盘故障会丢文件；后续可演进到对象存储（S3/MinIO）后端，对 `local_path` 抽象为 storage backend。
- **签名 URL 泄露**：签名 URL 在有效期内谁都可下载；按需缩短有效期或改为令牌校验。
- **重试风暴**：失败任务大量堆积时，限制重试频率与并发，避免打满上游。

## 12. 阶段建议（落地顺序）

1. **Phase 1（最小可用）**：数据模型 + 下载工作器（固定并发）+ 查询门控 + 本地文件服务（签名 URL）。后台仅"列表 + 重试 + 删除"。
2. **Phase 2**：设置项可配（并发/目录/超时/保留）+ 响应脱敏完善 + 文档更新。
3. **Phase 3（可选）**：对象存储后端、磁盘水位告警、下载进度条、按渠道/分组灰度开关。
